# G04 - Paso 1.15 | Primera revisión semántica focalizada de COSMIC

**Objeto:** registrar evidencia real de código para los 37 focos de la matriz 1.14. **No cambia automáticamente ninguno de los 111 estados del Excel.**

**Fuentes:** `G04_14_Matriz_Validacion_Tecnica_COSMIC_111.csv`; controladores y servicios Java de `AgroRetorno-v1.0.0.zip` (comprobados en las rutas de GitHub citadas en G04_13). Línea base RF de G03, sin aprobación atribuida a G01.

## Hallazgos que afectan el conteo

1. **M045 y M097, entradas E:** en los controladores Java las operaciones solo reciben `Authentication` y `Model`, sin parámetros de consulta o identificadores proporcionados por el usuario. No se debe suponer E por el solo hecho de solicitar una pantalla. **Propuesta:** excluir esos dos E del conteo funcional de trabajo, salvo evidencia de un grupo de datos funcional explícito en la frontera. Esta propuesta requiere actualizar y recalcular el Excel una vez aceptada la decisión.
2. **M080:** P18 reúne dos roles: el encargado usa `estado` y el productor consulta por la identidad autenticada. Una sola E no es automáticamente aplicable a ambas variantes; dejar explicado el alcance al definir el proceso.
3. **M082:** el enlace JPA con `Solicitud` y el uso en `PrestamoResponse` no prueban por sí solos que deban contarse dos R, uno a D05 y otro a D04.
4. **M005/M010/M019/M024/M033/M044/M064/M069/M079/M096:** el controlador comunica resultado por mensaje flash y redirige; no equiparar automáticamente un mensaje de control con una salida X de datos funcionales.
5. **D08:** hay una pantalla accesible de consulta de historial; no excluir globalmente D08 como log técnico, pero documentar por qué cada W forma parte de un requisito funcional.

**Impacto hipotético, no aplicado:** si únicamente M045 y M097 resultaran excluidas y no se ajustara ningún otro movimiento, el total del modelo pasaría de 111 a 109 CFP; **109 no es aún un resultado validado**.
